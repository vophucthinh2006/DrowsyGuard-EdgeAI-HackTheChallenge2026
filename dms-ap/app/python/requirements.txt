# App Lab installs this with uv when the app is deployed (confirmed: App Lab
# uses uv to prepare python/requirements.txt packages). opencv-python/cv2 is
# reportedly pre-installed on the UNO Q image; listed anyway so `pip install
# -r` in bench/dev mode (off-device) still works standalone.
#
# tflite-runtime, not the full `tensorflow` package, when it's installable:
# this device is an embedded ARM SBC (QRB2210) running inference, not a
# training/dev machine, and tflite-runtime is the purpose-built,
# order-of-magnitude-smaller package for exactly that job.
#
# specs/02-development-standards.md DEV-092 update: the assumption this repo
# started with -- "dms-ap/ runs Python 3.11" (see specs/02 header table) --
# did not survive contact with the real device. The real App Lab base image
# (ghcr.io/arduino/app-bricks/python-apps-base:0.10.1) runs CPython 3.13,
# and tflite-runtime's last PyPI release (2.14.0) only ships wheels up to
# cp311 -- there is no cp313 wheel and none is coming. Pinning
# `tflite-runtime>=2.14` unconditionally makes `uv`'s resolver fail the
# ENTIRE `requirements.txt` (uv resolves it as one solve, not package by
# package), which is why mediapipe -- completely unrelated -- also came up
# "not installed" in the container logs. The python_version markers below
# make uv skip tflite-runtime on 3.12+ and take the `tensorflow` fallback
# instead, which `inference/blazeface_cnn_backend.py`'s
# `try: tflite_runtime except ImportError: tensorflow.lite` already expects
# -- that fallback just never got a chance to run while the install itself
# was failing.
mediapipe>=0.10
tflite-runtime>=2.14; python_version < "3.12"
tensorflow>=2.16; python_version >= "3.12"
pyyaml>=6.0
